知识库与记忆空间 对接指南

对应面板：account.html#/admin → 「知识库 · 记忆空间」卡。 本文可**直接整段交给另一个 AI**（第 8 节是作业单），也可由人照着做。

先理解职责，不然一定会配错：账号服务（本服务）不存知识库内容、不存记忆。 它只是网关 + 权限闸。你真正要装的是两个独立服务（知识库 = WeKnora 兼容、记忆 = MemHub 兼容）， 装完把它们的地址填进面板。
结论先说：不依赖任何特定系统。
知识库（WeKnora）与记忆（MemHub）都是独立的上游服务，本服务只通过 HTTP + API Key 对接它们 —— 所以它们可以装在 任意 Linux 服务器 / 飞牛 OS / 群晖 / 威联通 / 一台只跑 Docker 的机器 上， 甚至两个服务分装在两台机器。本服务的记忆空间与知识库功能完全不关心它们跑在哪。
下文以飞牛 OS 举例（它自带应用中心与容器管理，最省事）；换到别的系统时，把「应用中心」换成 docker run / docker compose 即可， 后面的「拿 API Key」「在面板填地址」这些步骤完全一致。

1. 需要安装什么（一句话版）

要装的东西作用端口示例鉴权头
WeKnora（或兼容其 v1 API 的实现）存文档、切块、检索、给每个账号发只读 MCP 检索端点8080X-API-Key
MemHub（或兼容其 v1 API 的实现）存记忆条目、按会话召回、提供 MCP 读写端点8090Authorization: Bearer
⛔ 最容易错的一处：知识库用 X-API-Key，记忆用 Bearer。 把租户 Key 塞进 Authorization: Bearer 会稳定返回 401 invalid or expired token（那不是 key 错，是头的类型错了）。

2. 部署前提（任意 Linux / NAS 通用）

  • 飞牛OS 能开容器（Docker / Compose）或装套件；两个服务各占一个固定端口。
  • 给 NAS 一个固定的局域网 IP（下文用 192.168.1.10 举例）。
  • 账号服务所在的机器必须能直连这两个地址 —— 同内网最简单。
  • ⛔ 不要填 localhost / 127.0.0.1：账号服务通常不在 NAS 上， 回环地址指向它自己（实测：账号服务在公网服务器上时，127.0.0.1:7864 是那台服务器自己的 7864）。
  • 如果账号服务在公网云服务器、NAS 在家里：需要打通（VPN / 内网穿透）， 或把账号服务也放到内网。

3. 装知识库（WeKnora）

3.1 先看应用中心 / 镜像市场有没有（飞牛、群晖、威联通都有）

如果有现成的「知识库 / WeKnora / RAG」类应用：直接装，记下访问地址与端口，跳到 3.3。

3.2 没有就自己跑容器

把下面模板里的镜像名换成本项目发布页给出的镜像（本文不写死镜像名， 因为上游发布页才是唯一真相源）：

# /vol1/docker/weknora/docker-compose.yml
services:
  weknora:
    image: <上游发布页给出的镜像>:<版本>
    container_name: weknora
    restart: unless-stopped
    ports:
      - "8080:8080"          # 左边是 NAS 端口，右边是容器端口（以镜像文档为准）
    environment:
      # 上游要求的管理员/租户初始化参数（以发布页为准）
      - TZ=Asia/Shanghai
    volumes:
      - ./data:/data
cd /vol1/docker/weknora && docker compose up -d
docker compose logs -f --tail=50      # 看到 "listening"/"started" 之类即成功
判据（不看文档也能确认它在跑）：在 NAS 上执行 
curl -sS -o /dev/null -w '%{http_code}\n' http://192.168.1.10:8080/api/v1/knowledge-bases?page_size=1
401 / 403 = 服务活着（只是没带 key）→ 进 3.3；
404 = 端口通了但路径不对（少了 /api 前缀，或版本不同）；
超时 / 连接被拒 = 容器没起或端口映射错。

3.3 拿到「租户 API Key」

  1. 浏览器打开 http://192.168.1.10:8080，按上游首次启动向导建管理员/租户。
  2. 在「租户 / 设置 / API」里创建或复制一个 租户 API Key（不是登录 JWT）。
  3. 用它验证：
curl -sS -H "X-API-Key: <租户KEY>" \
  'http://192.168.1.10:8080/api/v1/knowledge-bases?page_size=1' | head -c 300
# 期望：JSON（可能是空列表），HTTP 200
若这里 401：key 复制错了，或用了 JWT 而不是租户 Key。

3.4 本服务会调它的哪些接口（兼容性对照）

方法路径用途
GET/api/v1/knowledge-bases?page_size=1连通性探测 / 列库
POST/api/v1/knowledge-bases给账号建库
PUT/api/v1/initialization/config/{kbId}配 LLM / 嵌入 / 视觉模型
POST/api/v1/mcp-endpoints建只读检索端点
GET / POST/api/v1/knowledge-bases/{id}/knowledge[/file]列 / 上传文档
POST/api/v1/knowledge-search检索

4. 装记忆（MemHub）

4.1 同上：应用中心优先，没有就起容器

应用中心有就装；没有就用容器跑，端口示例 8090。

4.2 判据

curl -sS -o /dev/null -w '%{http_code}\n' http://192.168.1.10:8090/
# 任何 < 500 的状态码（含 404）都说明 HTTP 栈活着

记忆服务没有统一的公开健康端点，所以「能收到 HTTP 响应」就算通。

4.3 拿 API Key

在 MemHub 的管理界面/环境变量里拿到 API Key，验证：

curl -sS -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer <KEY>" http://192.168.1.10:8090/
# 401 = key 不对；200/404/405 = 服务在（MemHub 在建用户端点上是 POST，GET 会 405，属正常）

4.4 两个地址的区别（配错会让"记忆带不上"）

面板字段走什么填错的表现
服务地址建用户、写记忆开通记忆直接报错
检索代理地址（MCP 网关）读取记忆能开通、能写，但新会话带不上记忆

5. 在面板上填

https://<你的域名>/account.html#/admin → 「知识库 · 记忆空间」卡

字段填什么留空会怎样
知识库 · 服务地址http://192.168.1.10:8080回退环境变量 WEKNORA_BASE
知识库 · 租户 API Key3.3 拿到的 key回退凭据 weknora-admin-key
知识库 · LLM / 嵌入 / 视觉 模型 id上游模型 id（如 qwen2.5:7b）回退 WEKNORA_*_MODEL_ID
记忆 · 服务地址http://192.168.1.10:8090回退 MEMHUB_BASE
记忆 · 检索代理地址MCP 网关地址回退 MEMHUB_PROXY_BASE
记忆 · 实例名一般 default回退 MEMHUB_INSTANCE
记忆 · API Key4.3 拿到的 key回退 memhub-admin-key
地址支持：https:// · http:// · 裸主机（自动补 https）· 内网 IP · 自定义端口 · 路径前缀。⛔ 内网请显式写 http://（否则会被补成 https，多半连不上）。

顺序：填地址 → 点「测试知识库 / 测试记忆」→ 看到 ✓ → 点「保存（热生效）」。 保存后不需要重启账号服务。卡头会一直显示「知识库生效 … · 记忆生效 …」，那是当前真正在用的地址。

7. 验收清单（以用户侧为准）

  1. 面板「用户 · 权益 · 积分」给某账号开通知识库。
  2. 用该账号登录云助手 →「知识库」标签：应显示已开通，不是"未开通/未授权"。
  3. 上传一个 .txt → 列表里出现该文档。
  4. 就文档内容提问 → 回答能引用到（说明 MCP 检索端点通了）。
  5. 「记忆空间」：对话几轮后新开会话，应能带上之前的要点。

8. 交给 AI 的作业单（可整段复制给另一个 AI）

你的任务：在这台飞牛OS（fnOS）上把「知识库」和「记忆空间」两个上游服务跑起来， 并让「账号服务」能连上它们。按下面顺序做，每一步都要先验证再进下一步。

1
确认环境：docker --version 有输出；ip -4 addr 记下 NAS 的局域网 IP（记作 NAS_IP）。
2
查应用中心是否已有知识库/记忆类应用；有则装，记录 KB_PORT 与 MEM_PORT。
3
没有则按第 3.2 / 4.1 节用 compose 起容器；镜像名必须从上游发布页取，不许猜。
4
验证知识库：curl -o /dev/null -w '%{http_code}' http://<NAS_IP>:<KB_PORT>/api/v1/knowledge-bases?page_size=1 ⇒ 期望 401/403（服务活着、只是没 key）。得到 200 也可以。
5
验证记忆：curl -o /dev/null -w '%{http_code}' http://<NAS_IP>:<MEM_PORT>/ ⇒ 期望 <500。
6
在知识库管理界面建租户、取 租户 API Key；用 -H "X-API-Key: …" 复验得到 200。
7
在记忆管理界面取 API Key；用 -H "Authorization: Bearer …" 复验（401 即 key 错）。
8
回到面板 /account.html#/admin → 「知识库 · 记忆空间」：按第 5 节填字段 → 点两个「测试」按钮 → 都必须出现 ✓ → 点「保存（热生效）」。
9
按第 7 节做 5 条验收。任一条不过，用第 6 节的表定位。

硬约束（违反会静默失效）：

  • ⛔ 地址不许填 localhost / 127.0.0.1（除非账号服务与上游同机）。
  • ⛔ 知识库的鉴权头必须是 X-API-Key，记忆必须是 Bearer。
  • ⛔ 内网地址要显式写 http://（裸主机默认补 https）。
  • ⛔ 改完必须点「保存（热生效）」；只点「测试」不会保存。

9. 与「模型池 / 闲时倍率」的边界

知识库/记忆用的模型（LLM / 嵌入 / 视觉）是上游服务自己去调的，不走本服务的「限时福利」网关，因此：

  • 不受 闲时倍率（offPeak）影响
  • 不从 本服务积分账本扣分

若希望它们也走本服务网关，需要在 WeKnora / MemHub 里把模型 base URL 指向 https://<你的域名>/cloud-api/proxy/v1 并使用网关密钥。这是可选做法，配错会两头不通。
