知识库与记忆空间 对接指南

两条部署路径（飞牛 OS / 服务器子域名）+ 面板配对。用于 Codex Harness 云端管理的「知识库」与「记忆」。

结论先说：不依赖任何特定系统。 两个上游都是独立开源服务，本服务只通过 HTTP + API Key 对接 —— 装在哪、装几台都不关心。可以两个都放飞牛，也可以知识库在 NAS、记忆在云服务器。

1. 两个项目分别是什么

能力开源项目本服务要连的端口
知识库WeKnora
github.com/Tencent/WeKnora		 8080（后端 API）
80 只是 Web UI
记忆空间TencentDB Agent Memory（Memory Hub）
github.com/Tencent/TencentDB-Agent-Memory		 8096（Proxy）
8125 只是管理面板
最容易配错的两处：
① 知识库别填 80（那是网页界面），要填 8080；
② 记忆别填 8125（管理员面板），要填 8096 的 Proxy —— Agent 的记忆注入走 Proxy。

2. 两条路径，任选其一

路径 A · 飞牛 OS（NAS） 图形界面：应用中心能搜到就一键装，搜不到就用 Compose 项目粘贴官方 yml。适合家里常开 NAS。
路径 B · 服务器 + 子域名 Linux 云主机 + Docker + Caddy 反代到 kb.域名 / mem.域名，带 HTTPS。适合有公网、多人共用。

两条路径装出来的东西完全一样，第 5 章「面板配对」对两者通用。

3. 路径 A：飞牛 OS

3.1 先看应用中心

  1. 飞牛 OS →「应用中心」搜 WeKnora / Memory Hub；有就装，记下端口。
  2. 没有就用「Compose 项目」——这是关键：WeKnora 要跑 5 个容器 （PostgreSQL+pgvector、Redis、DocReader、App、Frontend），手工一个个建必漏依赖， 直接粘贴官方仓库里的 docker-compose.yml 一步到位。

3.2 两个服务都要放的端口

服务容器必须映射出来
WeKnora官方 compose 定义的 5 个8080（另需 80 给网页界面）
Memory Hubcore / hub / proxy 三个8096（proxy）、8125（面板）
飞牛里跑容器同样吃内存。WeKnora 默认 5 个容器，小 NAS（4G）建议只开核心、别加 neo4j / minio 这些 profile。

4. 路径 B：服务器 + 子域名

4.1 装 Docker

curl -fsSL https://get.docker.com | sh
docker --version && docker compose version   # 两个都要有输出

4.2 部署 WeKnora（知识库）

git clone https://github.com/Tencent/WeKnora.git
cd WeKnora
cp .env.example .env
$EDITOR .env            # 至少填 LLM / Embedding 模型相关项

docker compose pull
docker compose up -d

# 确认 API 活着（这一步最关键，面板要连的就是它）
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/health

可选组件按需加（别一次全开）：

docker compose --profile neo4j up -d     # 知识图谱
docker compose --profile minio up -d     # 对象存储
docker compose --profile langfuse up -d  # 链路追踪

然后浏览器打开 http://服务器IP:80 → 注册 → 建知识库 → 上传文档 → 等文档状态变「已完成」。

4.3 部署 Memory Hub（记忆空间）

git clone https://github.com/Tencent/TencentDB-Agent-Memory.git
cd TencentDB-Agent-Memory/deploy/global-images
cp .env.example .env
$EDITOR .env     # 两组参数：
                 #   MEMORY_LLM_BASE_URL / MEMORY_LLM_API_KEY / MEMORY_LLM_MODEL
                 #   PROXY_UPSTREAM_URL  / PROXY_UPSTREAM_API_KEY / PROXY_UPSTREAM_MODEL

./start-all.sh   # 拉起 core + hub + proxy，自动初始化管理员、生成密钥
用途地址
管理面板（人看）http://服务器IP:8125
Proxy（本服务连这个）http://服务器IP:8096
管理员 keydeploy/global-images/.admin-key
官方要求 Node.js ≥ 22.16。start-all.sh 跑完会打印一条可直接复制的 Claude Code 启动命令 —— 那条命令能跑通，说明 Proxy 是通的，可以接着做配对。

4.4 绑子域名（可选，强烈建议）

# DNS：两条 A 记录
kb.你的域名   → 服务器IP
mem.你的域名  → 服务器IP

# Caddy：自动签发 HTTPS，两段就够
cat >> /etc/caddy/Caddyfile <<'EOF'
kb.你的域名 {
    reverse_proxy 127.0.0.1:8080
}
mem.你的域名 {
    reverse_proxy 127.0.0.1:8096
}
EOF
systemctl reload caddy
安全边界（官方明确要求）：这两个服务不要裸暴露在公网。
· WeKnora 自带登录，官方仍建议内网/私有网络部署；
· 用子域名对外时至少再加一层：Caddy Basic Auth / IP 白名单 / VPN；
· 记忆 Proxy（8096）等同于记忆的读写权限，拿到地址就能读写。

5. 在面板配对（两条路径通用）

1
拿知识库 Key：打开 WeKnora（:80）→ 登录 → 系统设置 / API Keys → 新建。 建议只给「检索」权限（scoped key），不要全量。
2
拿记忆 Key：Memory Hub 的 .admin-key，或另建一个业务用户用它的 key（admin 是运维口，别日常用）。
3
填面板：登录 https://你的云端管理域名/account.html → 侧栏「云端管理」→ 两张卡：
· 知识库：http://地址:8080 或 https://kb.你的域名 + 步骤 1 的 Key；
· 记忆：http://地址:8096 或 https://mem.你的域名 + 步骤 2 的 Key。
4
点「连通测试」。成功显示「端点已下发 / 凭据已保存」；失败会给具体原因。 改了地址或 Key 必须重测 —— 面板不会自动探测。
配对完成判据：「云端知识库」标签变绿「已接通」，「云端记忆」显示「已接通（请求层）」或「已接通（MCP）」。 新建会话后知识库会以 MCP 连接器形式挂上。

6. 排错对照表

症状多半是怎么查
连通测试超时端口填错（用了 80 / 8125）、防火墙没放行curl -v http://地址:端口/health
401 unauthorizedKey 复制错 / 用了别的服务的 Key重建一个 Key，注意别带空格换行
404地址带多余路径，或反代只转页面没转 API子域名下试 /api/… 是否可达
能连但检索为空WeKnora 里没建库 / 文档还没解析完面板看文档状态是否「已完成」
记忆「已接通」但对话带不上填了 8125 面板而不是 8096 Proxy改 8096 重测
容器起来又退出内存不够（WeKnora 默认 5 容器）docker compose logs app --tail=50
升级后界面版本对不上up -d 用了本地旧镜像先 docker compose pull 再 up

7. 验收清单

  • ☐ curl http://地址:8080/health 返回 2xx
  • ☐ curl http://地址:8096/ 有响应（不是 8125）
  • ☐ WeKnora 里至少一个知识库，文档状态「已完成」
  • ☐ Memory Hub 面板能登录（业务用户，非 admin）
  • ☐ 云端管理两处「连通测试」都通过
  • ☐ 新建会话后知识库出现在工具面（MCP 连接器）
