# 登录优先 · 本地轻量外壳 + 服务器驱动模块 —— 架构设计

> 2026-10-14 立（云助手）。本文是**登录闸重构（`ca17487`）之后的架构定版**：
> 一晚修不好配对/登录问题的根因是旧设计（shim 里拼配对卡、多层自愈、与启动图层级战争），
> 已按「没匹配应用不加载」删除重做。本文把新架构的职责边界、通信鉴权、缓存、降级、
> 加载顺序与扩展位一次说清，作为后续实现的单一真相源。

---

## 0. 一句话架构

**本地 = 登录闸 + 轻量外壳（窗口/托盘/IPC 桥/引擎进程管理）+ 模块加载器；
服务器 = 身份、模块清单与资产、业务数据、第三方服务代理、更新与遥测。**
未通过登录验证前，本地**不加载任何应用代码**（一道真正的闸，不是一个弹窗）。

---

## 1. 职责边界（本地 vs 服务器）

| 能力 | 本地（Electron 外壳 + 核心引擎） | 服务器 |
|---|---|---|
| 登录闸 / 配对页 | ✅ `/pair` 独立页、配对码生成、令牌交接 | ✅ 账号注册/登录、认领核销（`/device/claim*`） |
| 身份与令牌 | 持有本地令牌（`token` 文件 + 页面 localStorage） | 签发/校验/停用；设备绑定表 |
| 窗口 / 托盘 / 通知 | ✅ 独占 | — |
| IPC 桥（`window.codex` shim） | ✅ 独占（loopback `/__ipc` + SSE） | — |
| 引擎进程（codex app-server） | ✅ 独占（拉起/看护/清理） | — |
| 应用界面资产（app/） | 缓存 + 校验（**不产出**） | ✅ 产出与版本（`version.json` + sha256） |
| 功能模块（业务域） | 缓存 + 按需加载（**不产出**） | ✅ 模块清单（manifest）+ 资产 + 灰度 |
| 业务数据 / 配置 | 只读缓存（离线可见） | ✅ 真相源 |
| 第三方服务（LLM/搜索/网关） | — | ✅ 统一代理（令牌不落地到第三方） |
| 更新 | 触发 + 应用（下载/校验/替换） | ✅ 版本发布、通道、灰度 |
| 遥测 / 崩溃 | 上报（可关） | 汇聚 |

**铁律**：
1. 本地**不产出**任何业务资产（界面/模块/配置模板）—— 只缓存与校验；
2. 服务器**不持有**用户机器上的任何本地凭据（引擎会话、本地文件）；
3. 令牌只在「本地 ↔ 服务器」之间传递，**绝不转发给第三方**。

## 2. 启动与加载顺序（登录态校验 → 动态模块）

```
① 外壳静态 HTML（本地，零依赖）
        │  内联闸脚本（同步执行）：无 chc-token ⇒ location.replace("/pair")
        ▼
② /pair 配对页（自包含，无应用代码）
        │  配对码服务端直出；「打开授权页面」⇒ 主进程 shell.openExternal(网页 ?claim=码)
        │  网页注册/登录 ⇒ 自动认领 ⇒ 302 回 /auth/callback
        ▼
③ 令牌交接（同源）：/pair 轮询 cloud-state ⇒ machinePaired
        ⇒ /api/pair-token-for-callback?code=（服务端真相源校验）⇒ 写 localStorage ⇒ 跳回 /
        ▼
④ 闸放行 ⇒ 应用外壳加载（app/ 资产：本地缓存命中 or 服务器拉取+校验）
        ▼
⑤ 模块清单（GET /modules/manifest，带令牌）⇒ 版本协商（本地缓存 vs 云端最新）
        ▼
⑥ 核心模块（core：会话/输入/设置骨架）—— 必须先就绪，否则界面不可用
        ▼
⑦ 功能模块按需懒加载（路由级/面板级）：下载 ⇒ sha256 校验 ⇒ 缓存 ⇒ 挂载
        ▼
⑧ 运行期：账号状态轮询（停用 ⇒ 摘绑定 ⇒ 令牌失效 ⇒ 回 /pair）；401 ⇒ 回 /pair（闸重判）
```

**顺序即契约**：任何一步失败都**停在当前层并给出可操作提示**，不允许「带着坏状态往下跑」——
旧设计的一切鬼烟（401 循环、启动图永驻、令牌失配）都源于违背这条。

## 3. 网络通信与鉴权

| 通道 | 用途 | 鉴权 |
|---|---|---|
| `http://127.0.0.1:<port>`（loopback） | 外壳 ↔ 本机服务（`/__ipc`、`/__events` SSE、`/api/*`） | `Authorization: Bearer <本地令牌>` + `x-harness-client: web` + **Origin 白名单**（deny 403） |
| `https://ppz123.asia/cloud-api` | 账号/设备/模块清单/更新/遥测 | 同上 Bearer；账号登录用一次性票据 |
| `https://ppz123.asia/cloud/app/`、`/modules/` | 资产下载 | 公开读（无敏） + **sha256 清单校验**；清单本身带令牌 |

**边界规则**：
- loopback 只监听 `127.0.0.1`，**不绑 0.0.0.0**（手机远程走独立端口 + 配对码，另行鉴权）；
- 每个 `/api/*` 逐一过闸（origin + token），**静态外壳不过**（它要自己消费 `#t=`/配对页）；
- 账号被停用 ⇒ 绑定被摘 ⇒ 轮询发现 ⇒ 令牌立刻失效（失败放行：服务不可达不误杀）；
- 错误码固定：`origin-not-allowed` / `unauthorized` / `not-claimed` / `account-disabled` / `accounts-unreachable`。

## 4. 缓存策略

| 缓存 | 位置 | 失效 |
|---|---|---|
| 界面/模块资产（app/、modules/） | `userData/asset-cache/<版本>/` | `version.json` 版本号 + 文件 sha256；新版全量切换，旧版保留一份回滚 |
| 模块清单 | 内存 + 磁盘（带 `fetchedAt`） | TTL 10 分钟；登录/更新时强制刷新 |
| 业务数据（会话索引、公告、设备列表） | 内存 + 磁盘（只读副本） | 每次成功拉取覆盖；**离线只读**（标注数据时间） |
| 本地令牌 | `~/.codex-harness-cloud/token`（0600）+ 页面 localStorage | 断开连接/被摘绑定即删 |
| 账号票据 | 内存 only | 一次性 |

**铁律**：缓存**永不被当作真相源**——任何写操作必须到达服务器成功后才更新本地视图；
sha256 不符的资产**拒绝加载并回退上一版**（不静默用坏资产）。

---

## 5. 离线降级（分级，不搞一刀切）

| 级别 | 触发 | 行为 |
|---|---|---|
| L0 登录不可用 | 账号服务不可达 / 未配对 | 停在 `/pair`（配对页本身可用：出示码、退出）；**明确告知"需要联网完成首次连接"** |
| L1 已登录、资产不可达 | 模块/资产下载失败 | 用本地缓存版（标注"离线模式"）；无缓存 ⇒ 停在骨架屏 + 重试按钮 |
| L2 已登录、业务数据不可达 | 数据接口失败 | 展示缓存数据（只读、带时间戳）；写操作进**待同步队列**，恢复后按序重放 |
| L3 服务器不可达、本地能力可用 | 任意远端失败 | 引擎本地会话、本地文件、设置照常（这些本就是本地能力） |

**铁律**：降级**必须可见**（界面标注状态），不允许"静默用旧数据冒充最新"。

---

## 6. 登录态校验

1. **闸（前置）**：无令牌 ⇒ `/pair`（§2①）；
2. **每次请求**：Bearer + Origin 双验；
3. **401（运行期）**：清令牌 ⇒ 回 `/pair`（闸重判，配对码认领前一直有效 ⇒ 重新认领即恢复）；
4. **周期校验**：账号状态轮询（`claim-status`，已绑定后 5s→60s 退避）；停用/摘绑立即失效；
5. **令牌刷新位**：账号服务下发长期令牌 + 可撤销（设备解绑即撤销）；无需 refresh token
   （撤销优先于轮换，实现更简单、撤销更即时）。

---

## 7. 安全边界

- **CSP**：外壳逐条独立（`connect-src` 含 loopback + 云端源；`img-src`/`script-src` 按需扩）；
- **不 eval 远端代码**：模块资产必须是**静态 JS + sha256 清单**；禁止 `eval`/`new Function` 远端串；
- **令牌不进日志/URL**：fragment 交接（`#t=`）+ 请求头；错误信息只返回码不返回令牌；
- **配对码即凭据**：仅在本机可见处出示（配对页/控制台）；换令牌端点必须**服务端真相源校验**（已补的洞）；
- **Origin 白名单 + loopback 绑定**：本地服务不暴露局域网（远程能力独立端口 + 单独鉴权）。

---

## 8. 扩展位（为什么这样拆）

| 扩展 | 挂点 |
|---|---|
| 新功能模块 | 服务器模块清单加一行（名字/版本/sha256/入口/依赖/灰度%）—— 本地零改动 |
| 新业务域（A+ 会话索引 / B 云端执行） | `/api/cloud-state` 已下发 `plan` + `cloudFeatures` 两个能力位，界面按位渲染 |
| 新鉴权方式（OAuth 第三方） | 账号服务加 provider；本地闸与令牌交接**不变** |
| 灰度/回滚 | 清单版本号 + 资产多版本共存（旧版保留一份） |
| 新第三方服务 | 服务器代理统一收口（令牌不落地第三方） |

---

## 9. 落地现状与路线

**已落地（本轮）**：
- 登录闸重构（`ca17487`）：`/pair` 独立配对页 + 闸重定向 + 401 回配对页 + 旧 shim 配对卡删除；
- 账号服务（注册/登录/停用/删除/设备认领/claim-status）、令牌服务端校验；
- 判据：端到端 8/8（shim 语法 / 闸重定向 / 旧卡零残留 / 配对页零应用代码 / 码服务端直出 / 三按钮齐）。

**下一步（按序）**：
1. 模块清单 + 资产缓存（`/modules/manifest` + `asset-cache` + sha256 校验）——本地加载器；
2. 核心模块/功能模块拆分（界面从"一整包 dist"改为"核心 + 按需模块"）；
3. 业务数据只读缓存 + 待同步队列（L2 降级）；
4. 账号状态轮询与停用摘绑的运行期闭环（§6.4 已有雏形）；
5. 更新通道与设备令牌打通（`/device/update/*`）。

**每条落地都必须带机器判据**（守卫/端到端），不许再出现"改了没生效/修不好"的夜游循环。
