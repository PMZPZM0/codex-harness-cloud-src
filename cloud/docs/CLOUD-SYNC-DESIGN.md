# 跨账户 / 跨设备同步 —— 完整方案（项目 · 会话 · 记忆）

> 2026-10-14 立。目标：把**项目与会话上传云端**，实现跨账户/跨设备同步记录；用户中心从「只有账号信息」升级为「账号 + 设备 + 同步 + 用量」。
> 本文以**实测数据落点**为基础（不是凭空设计），是后续实现的单一真相源。

---

## 0. 现状：数据到底存在哪（实测）

| 数据 | 位置（本机） | 结构 | 对同步的意义 |
|---|---|---|---|
| **会话正文（rollout）** | `$CODEX_HOME/sessions/<年>/<月>/<日>/rollout-<时间>-<sessionId>.jsonl` | **每行一个事件**：`{timestamp, ordinal, type, payload}`，`session_meta` 首行带 `session_id` / `cwd` / workspace roots | ⭐ **append-only + ordinal** ⇒ 可做**行级增量**，两端各自追加也能拼回去（天然无冲突） |
| 会话索引 | 由 rollout 推导（标题/时间/cwd/用量） | 无独立文件 | 云端物化一份索引即可"先看见再下载" |
| 项目 / 分组 / 命名 | 由会话 cwd 推导 + 用户覆盖（名称/分组/颜色） | 用户覆盖是小元数据 | 同步会话 = 项目自动出现；只需同步"覆盖项" |
| 项目记忆 | `<workspace>/.codex-harness/memory/*`（记忆金字塔/结论档案） | 条目（md / jsonl） | 可选同步，条目级合并 |
| 技能 / 命令 | `$CODEX_HOME/skills`、`<cwd>/.codex/skills` | SKILL.md + 附件 | 可选同步（用户自建的那部分） |
| 设置 / 偏好 | `<userData>/*.json` | 键值 | 可选同步，**必须白名单**（见 §1） |
| 凭据 / 密钥 | `openai-vault`、连接器凭据、设备令牌 | — | ⛔ **绝不同步**（只留本机） |

**关键结论**：会话是"**追加型事件流**"，这让同步从"文件级覆盖"升级为"行级追加"，是整套方案能既简单又不丢数据的基础。

## 1. 同步范围与粒度

### 1.1 范围（默认值即推荐值）

| 类别 | 默认 | 粒度 | 说明 |
|---|---|---|---|
| **会话正文** | ✅ 同步 | **单个 rollout 文件的行**（按 `ordinal` 追加） | 核心能力；不含图片二进制（见 1.2） |
| **会话元数据** | ✅ 同步 | 记录（sessionId） | 标题、时间、cwd 逻辑名、用量统计、归档/收藏标记 |
| **项目覆盖项** | ✅ 同步 | 记录 + 字段 | 项目**逻辑 id**、显示名、分组、颜色、排序 |
| 项目记忆 | ⬜ 默认关 | 条目（每条一个 id） | 打开后按条目并集合并（`.codex-harness/memory` 下的 md/jsonl） |
| 技能 / 自定义命令 | ⬜ 默认关 | 文件（SKILL.md 及其附件） | 用户自建的才同步；内置的不传 |
| 设置 / 偏好 | ⬜ 默认关 | 白名单键 | 只允许：模型 id、供应商**名称**（不含 key）、外观/主题、语言、快捷键 |
| 附件 / 截图 | ⬜ 默认关 | 二进制（对象存储） | 打开后走对象存储 + 引用；默认只同步文本与"图片存在"的占位 |

### 1.2 明确排除（黑名单，写死在引擎侧，不可被设置打开）

- ⛔ API Key / `openai-vault` / 连接器凭据 / 设备令牌 / 本机令牌 → **永不离开本机**
- ⛔ 沙箱策略、exec 策略、hooks → 安全边界，跨机复制等于降级防护
- ⛔ `.env*`、`*.pem`、`id_*`、`credentials*` 等敏感文件名（正则黑名单，命中即跳过并记审计）
- ⛔ 大二进制（默认 >2 MB 不上传；打开"附件同步"后走对象存储）
- ⛔ 机器标识（`installation_id`）→ 只用于设备行，不随同步走

### 1.3 粒度实现（为什么是"行"）

```
本地 rollout 文件                     云端对象
─────────────────────────────        ─────────────────────────────
{ordinal:0 ... session_meta}          <tenant>/sessions/…/<sessionId>.jsonl
{ordinal:1 ... user_message}    ──►   已追加 ordinal 0..N
{ordinal:2 ... tool_call}             （服务端记录 {maxOrdinal, totalBytes, headHash}）
{ordinal:3 ... assistant}   ← 只追这行
```

- 本机记 `syncedOrdinal`（每文件一行状态）；上传 = 只取 `ordinal > syncedOrdinal` 的部分；
- 服务端按 `(sessionId, ordinal)` **幂等**写入（重复上传不产生重复行）；
- 上传前校验 `headHash`（前 N 行的 sha256）——不一致说明历史被改过（人工编辑过 rollout）⇒ 走"冲突副本"而不是覆盖。

## 2. 账户切换：同步机制与冲突处理

### 2.1 空间模型

```
账号 A ──┐                      一个账号 = 一个同步空间（tenant）
账号 B ──┼── 空间 = 该账号的     设备 = 空间成员（已有 registry，用设备令牌鉴权）
账号 C ──┘   会话 + 项目 + 记忆
```

- 本地**不复制会话文件**（`$CODEX_HOME/sessions` 仍是一份），而是维护**归属索引**：
  `<userData>/sync/spaces/<accountId>/state.json`（哪些 sessionId 属于该空间 + 各自的游标）；
- 界面按**当前账号**过滤列表：切到 B 只显示 B 的会话，切回 A 立刻恢复（数据一直在本机，零拷贝）。

### 2.2 切换时序

```
用户切账号（或断开重连到另一个号）
  ① flush：把当前空间的未上传队列推到服务端（失败则保留 pending 标记，不阻塞切换）
  ② seal：写死当前空间的游标快照（下次切回按它继续，不重扫）
  ③ switch：activeSpace = 新账号；界面清屏 + 拉该空间索引（元数据优先，正文按需拉）
  ④ merge：把该空间云端索引与本地已有会话做并集（本地已有的不重复下载）
  ⑤ 提示：若新空间在本机从没见过 ⇒ 空列表 + "正在拉取…"进度（不是错误）
```

### 2.3 冲突处理（按数据类型分级，**不静默覆盖**）

| 数据类型 | 规则 | 说明 |
|---|---|---|
| 会话正文（rollout） | **行级合并**（按 ordinal 拼接） | 两端各自追加 ⇒ 并集即可；同 ordinal 不同内容（人工改过）⇒ 保留两份，云端副本标 `(来自 <设备> 副本)` |
| 会话元数据（标题/收藏） | 记录级 **LWW** + 字段级合并 | 名字改了 vs 收藏改了 ⇒ 两个都对，都保留 |
| 项目覆盖项 | 同上（字段级） | 分组与颜色独立字段，互不覆盖 |
| 记忆 / 技能（条目） | **并集** + 条目内 LWW | 每条自带 id + 时间戳，天然可合并 |
| 设置项 | 字段级 LWW | 冲突极少；白名单内才同步 |
| 删除 | **墓碑**（`deletedAt`） | 否则"删掉的会话下次拉取又回来" |
| 真冲突（同字段双改且都非空） | **生成冲突项并列出**，用户在用户中心点选 | 绝不静默丢一边 |

## 3. 云端存储 ↔ 本地数据的对应关系

### 3.1 云端布局（对象存储或服务器磁盘，同一套 key）

```
<tenant>/index.json                     会话索引（id/标题/时间/项目/用量/rev）
<tenant>/projects.json                  项目覆盖项（逻辑 id + 显示名/分组/颜色）
<tenant>/sessions/<y>/<m>/<d>/<sid>.jsonl      会话正文（与本地同构 ⇒ 便于逐行对比）
<tenant>/memory/<scope>/<id>.md         记忆条目（可选）
<tenant>/skills/<name>/**               技能（可选）
<tenant>/_trash/<sid>.<ts>              墓碑归档（保留 30 天）
```

- **与本地同构**是刻意设计：同一份"年/月/日/会话id"层级，让"这个文件有没有同步过"一眼可比；
- 服务端不解析会话内容（除索引推导），**明文/密文无关**（见 §4.4）。

### 3.2 本地状态（唯一真相源之外的全部同步状态）

```jsonc
// <userData>/sync/spaces/<accountId>/state.json
{
  "spaceId": "u_admin",
  "cursor": "sv-1042",                    // 服务端变更游标
  "sessions": {
    "01a11ad8-…": { "path": "sessions/2026/10/08/rollout-…jsonl",
                    "syncedOrdinal": 12, "headHash": "…", "sizeBytes": 8213,
                    "rev": 7, "dirty": false, "deletedAt": 0 }
  },
  "projects": { "<uuid>": { "rev": 3, "dirty": false } },
  "pending": [ { "op": "append", "sid": "…", "from": 12, "to": 18 } ]
}
```

- 本地 `sessions/**` 是**唯一正文真相源**；state.json 只记"同步到哪了"（可随时删掉重建，代价是全量重扫）；
- **路径不进云端**（隐私 + 跨机路径本就不同）：云端只认 `sessionId`，本机路径 ↔ id 的映射留在本地。

### 3.3 同步协议（增量、幂等、可续传）

```
客户端 → GET  /sync/pull?cursor=<c>                  ← 返回变更列表(元数据+每个对象的目标 rev/size/hash)
客户端 → POST /sync/push  { sessionId, fromOrdinal, lines:[…], headHash, contentHash }
服务端 ← 按 (sessionId, ordinal) 幂等写入；返回新 cursor 与 maxOrdinal
客户端 → POST /sync/meta  { indexDelta, projectsDelta }      ← 元数据（LWW + 墓碑）
```

- **断点续传**：push 带 `fromOrdinal`，服务端返回已收到的 `maxOrdinal` ⇒ 从中断处继续；
- **失败重试**：指数退避（5s→30s→2min→10min），离线队列持久化到 state.json（重启不丢）；
- **节流**：会话写入触发 watcher（复用现有 `turn-file-watch`）⇒ 入队 ⇒ 空闲或每 30s 批量推。

## 4. 功能模块划分与交互流程

### 4.1 模块划分（每块一个独立板块，遵守 ARCHITECTURE-RULES）

| 层 | 模块 | 职责 |
|---|---|---|
| 主进程 | `electron/features/sync-ipc.ts`（域前缀 `sync`） | 唯一对外 IPC 面：状态/开关/范围/立即同步/冲突列表/解决 |
| 主进程 | `electron/sync/engine.ts` | 扫描（rollout 增量）→ 打包 → 上传 → 应用（pull）→ 游标/重试（后台单例） |
| 主进程 | `electron/sync/scope.ts` | 范围判定 + 黑名单（凭据/敏感文件/大文件；**单一真相源**） |
| 服务器 | `cloud/server-account/sync-service`（同一进程内新路由） | 鉴权（设备令牌，已有）/ 对象读写 / 索引物化 / 配额 / 墓碑清理 |
| 渲染层 | 用户中心「跨设备同步」卡片 + 冲突列表 | 开关、范围勾选、用量、最近同步时间、手动同步、冲突解决 |
| 渲染层 | 账户切换入口 | 切换前提示"正在同步 X 项 / 未同步的会保留在本机" |

### 4.2 交互流程 A：日常（会话产生 → 云端）

```
引擎写 rollout（本机） → sync engine 的 watcher 命中 → 入队（标记 dirty）
   → 空闲/30s → 批量 push（只传新行）→ 服务端幂等写入 → 回写 syncedOrdinal
   → 用户中心显示"最近同步：刚刚 · 本空间 128 会话 / 4.2 MB"
```

### 4.3 交互流程 B：新设备 / 换号

```
登录（或切号） → 拉索引 → 列表立刻可见（标题/时间，元数据优先）
   → 点开某会话 → 若正文未下载 ⇒ 拉该会话全量 → 落本地 sessions/ 同构路径
   → 项目覆盖项（名称/分组/颜色）同步回来；本机找不到对应目录的项目标"待认领目录"
     （由用户选一次目录；⛔ 不自动猜路径）
```

### 4.4 交互流程 C：安全与隐私档位（默认档可改）

| 档位 | 服务端可见 | 代价 |
|---|---|---|
| **标准（默认）** | 可读（索引可服务端物化、可管理端检索） | 依赖服务器信任 |
| **端到端加密** | 只存密文 | 云端无法检索/管理；换设备需账号口令派生密钥（丢失不可恢复） |

密钥策略：由账号口令经 KDF（Argon2id）派生 + 设备侧保存一份受 OS 保护的包裹密钥；用户中心可一键切换档位（切换=重传，旧密文归档）。

### 4.5 配额与边界行为

- 每账号配额（建议：1000 会话 / 500 MB，可配）；超限 ⇒ **只读**（不再上传，本地照常记录，界面明示"已达配额，未同步 N 项"）——⛔ 绝不静默丢数据；
- 服务端保留墓碑归档 30 天（回收站语义）；
- 单文件上限（默认 8 MB/会话，超限截断并标记"部分同步"）。

## 5. 实施阶段（每阶段都可独立上线、都有机器判据）

| 阶段 | 内容 | 判据 |
|---|---|---|
| **P0** | 索引 + 单向上传（本机 → 云端，仅会话正文与元数据） | 上传后服务端对象与本地逐行一致；重复上传无重复行 |
| **P1** | 拉取 + 行级合并（新设备只见标题、点开拉正文） | 造两台"设备"（不同 userData）互传：并集正确、无重复 |
| **P2** | 账户切换空间隔离 + 冲突列表与解决 UI | 切号后列表按空间过滤；同字段双改产生冲突项并可解决 |
| **P3** | 范围开关（记忆/技能/设置白名单）+ 用量与配额 | 关掉的项目不上传；配额超限进只读并如实显示 |
| **P4** | 端到端加密档位 + 墓碑回收站 | 切档后服务端只见密文；删除的会话不被拉回 |

## 6. 与现有机制的关系（不重复造）

- **鉴权**：直接复用设备令牌通道（`/device/*` 已有 `findDeviceByToken`）⇒ 同步接口天然带身份与账号绑定；
- **会话监听**：复用 `turn-file-watch.ts`（已在监听 rollout 变化）⇒ 同步引擎只是多一个订阅者；
- **发布**：同步服务随 `server-account` 一起部署（同一 systemd 单元），界面改动走 `deploy:web` / `deploy-app`；
- **账户绑定**：同步空间的 id 直接用 `accounts.json` 的 owner（已有的绑定关系），不新增一套账号体系。
