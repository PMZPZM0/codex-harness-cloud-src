# cloud-v0.0.3 发版说明（Codex Harness Assistant）

本版主题：**修好「装完什么都看不到」** —— 外加 0.0.2 的全部修复（启动崩溃 / 更新线隔离 / 自动更新）。

> ⛔ 仍然请勿使用 v0.0.1 / v0.0.2 的旧包：v0.0.1 装完即崩；v0.0.2 能跑但**启动后不出现任何界面**
> （无窗口、不弹浏览器、托盘也没有入口）——本版修复。

## 一、本版修复（0.0.2 → 0.0.3）

- **启动后自动打开界面**：助手启动约 1.5 秒后自动用系统默认浏览器打开本地界面
  （`http://127.0.0.1:8917`）。此前装完好比没装：服务在跑、托盘图标在，但用户面前什么都不出现，
  也看不到配对框。
- **托盘新增「打开助手界面」**：不小心关掉浏览器标签页后，右键托盘图标即可重新打开
  （界面、配对框都从这进）。
- **对话框**：选文件 / 选目录走系统原生对话框（app-modal，不依赖窗口可见），与桌面版交互一致；
  无头远程场景可用 `HARNESS_DIALOG_MODE=cancel` 让无答案时按取消处理，不会干等。
- **独立窗口**：无头形态下「独立窗口」改为在默认浏览器里弹独立标签页（同一套界面、同一份 shim），
  不再依赖永远隐藏的 Electron 窗口。

## 二、0.0.2 已带上的修复（本版同样包含）

- **安装后启动崩溃**：打包清单补 `src/lib/*.mjs` 与托盘图标资源；
- **更新线独立**：助手只认 `cloud-v*` 标签 + `CodexHarnessAssistant-*` 资产，不会再抓桌面版的
  v0.0.39 当自己的更新；
- **自动更新完整链路**：启动 30 秒后首查、之后每 6 小时、失败退避（5 分钟 → 15 分钟 → 1 小时 → 6 小时）；
  下载有速度 / 剩余时间；可取消、断点续传、稍后安装、跳过版本；
- **覆盖安装卡死**：安装程序 preInit 强杀托盘常驻进程；
- **mac 托盘图标**：改用 PNG（electron-builder 的 mac 目标不认 .ico）；
- **三端齐全**：Windows + mac Apple 芯片 + mac Intel。

## 三、这是什么（首次使用请看）

Codex Harness 的**应用版客户端**：本地助手跑引擎与真界面，浏览器或本应用都能用；登录与界面更新走
ppz123.asia，**会话与数据全部在你自己的电脑上**。

- 双击安装即用；引擎内置（Codex 官方二进制）
- 连接云端服务器：注册/登录 → 输配对码 → 多设备管理
- 事件实时推送（SSE），非轮询
- 工具链（Node/Python/rg 等）按需下载（国内镜像），安装包保持精简

## 四、安装

**Windows**：下载 `CodexHarnessAssistant-0.0.3-win-x64-setup.exe` → 双击安装 → 完成后自动启动并打开界面。

**macOS**：
1. 下载对应芯片的 zip（Apple 芯片选 `arm64-mac.zip`，Intel 选 `x64-mac.zip`）；
2. 在「下载」里解压，把 **Codex Harness Assistant.app** 拖进「应用程序」；
3. 首次打开若提示无法验证开发者：打开「终端」，输入 `xattr -cr `（注意末尾有空格），**把 app 图标拖进终端自动填全路径**，回车后再双击打开；
4. 若提示已损坏（错误码 640）：同样是上面的 `xattr -cr <路径>` 命令，执行一次即可；
5. 仍打不开时：系统设置 → 隐私与安全性 → 仍要打开。

## 五、首次使用

1. 启动后自动打开界面（若没弹出来，浏览器手动访问 `http://127.0.0.1:8917`，或右键托盘 → 打开助手界面）；
2. 首次使用会要求配对：到 https://ppz123.asia 注册/登录 → 输入本机签发的 8 位配对码；
3. 在「设置 → 模型」里填入你自己的模型账号；
4. 开始使用。此后每次开机启动助手，任何浏览器打开 https://ppz123.asia 登录即连。

## 六、已知问题

- 工具链按需下载的服务端分发目录仍在准备中：MCP/脚本类能力可能降级（引擎与对话不受影响）；
- 配对码目前只能由本机命令行签发（`Codex Harness Assistant.exe --add-user 名字`，只在签发时打印一次），
  界面内一键签发是下一版的事。
